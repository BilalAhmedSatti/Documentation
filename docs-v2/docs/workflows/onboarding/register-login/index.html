Step 01 · Channel into the platform

Presenter cheat sheet
  • Start here: “Nobody reaches PostgreSQL from the browser.”
  • Name the three actors: Customer → apps/web → BFF.
  • Redis here is only rate-limiting, not customer data.
  • If asked “is the user registered yet?” — No. Credentials are saved in the next step.

Step-by-step walkthrough

#ComponentWhat happensDurable write
01 Customer A real person opens the bank app and taps Register or Login. That is the only human action in this step.
Every onboarding journey starts with a channel action, not a database write.
Point at START Customer — human entry.		 Nothing saved yet
02 apps/web The React app collects email and password, validates the form, and sends HTTPS to the BFF. The browser never opens a DB connection.
Keeps secrets and routing off the client; UI is only a form.
Point at apps/web — UI only.		 Nothing durable in the browser
03 services/bff The BFF figures out which bank/market this request belongs to, can bump a Redis counter to block brute-force, then forwards auth to identity.
One gateway for all channel calls; multi-market rules start here.
Point down the purple arrow into Redis if you mention throttling.		 Optional Redis INCR on rate-limit keys (throttle only — not customer data)
04 Hand-off We stop here on purpose. The next slide is where identity hashes the password and inserts the credentials row in PostgreSQL.
Separates “enter the platform” from “save credentials”.
Point at END — teaser for Step 02.		 No customers INSERT in this step
