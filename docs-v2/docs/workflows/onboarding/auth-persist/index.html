Step 02 · Credentials saved

Presenter cheat sheet
  • Call out: “This is the first PostgreSQL INSERT in onboarding.”
  • Never store plain passwords — only a hash.
  • Login uses the same credentials table (SELECT), register uses INSERT.
  • Still no customers profile row — that is Step 04.

Step-by-step walkthrough

#ComponentWhat happensDurable write
01 services/bff BFF already knows the market. It forwards the register or login body to identity.
Channel never calls identity DB tables itself.
Point at START BFF.		 Nothing saved yet
02 identity Identity hashes the password and writes email, name, and hash into PostgreSQL credentials.
Auth must be durable before we create a customer profile.
Point at the purple INSERT box — main teaching moment.		 INSERT → PostgreSQL 16 (credentials)
03 JWT / session A token goes back to apps/web. The customer is signed in for the next screens.
Later APIs need an authenticated caller.
Point at END — signed-in state.		 Token on the client — secret never stored plain
